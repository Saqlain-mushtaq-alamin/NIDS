# Phase 3 Summary — Anomaly Detection, GNN, Drift Monitoring, and Fusion

**Status:** complete. 196 tests pass, 1 skipped. All experiment gates met.

> ## Read this before any number below
>
> **Every performance figure in this document was produced on synthetic data.**
>
> - The Phase 2 flow captures (`data/lab_captures/lab_flows.csv`, 16,043 flows)
>   are stand-ins generated by `src/data/traffic_model.py`. The published
>   datasets (CIC-IDS-2017, UNSW-NB15) could not be obtained in this
>   environment.
> - The host-graph data comes from `src/data/graph_simulator.py`, written for
>   this phase. The real lab captures contain only three addresses
>   (`10.0.0.5` → `10.0.0.10` / `10.0.0.15`) and cannot form a host graph with
>   enough nodes to learn from. Phase 2 data was left untouched.
>
> These results therefore demonstrate that **the pipeline is correct, the gates
> are met, and the failure modes are understood**. They are **not** a claim about
> real-world detection quality. Section 6 states precisely what would and would
> not survive contact with real captures.

## 2. Results

### 2.1 Flow autoencoder (`lab_flows`, 28 features, latent dim 16)

| Metric | Value |
|---|---|
| Detection rate | 0.606 |
| False-alarm rate | 0.016 |
| ROC-AUC | 0.953 |
| Average precision | 0.990 |
| Threshold (99th pct of validation-benign error) | 1.379 |
| Benign training rows used | 1,881 |
| Attack training rows **excluded** | 9,348 |

Two rules the implementation enforces rather than trusting the caller:

1. **Fitted on benign rows only.** Training on a mixed set teaches the network
   to reconstruct attacks as well as benign traffic, which destroys its ability
   to score them as anomalous. Attack rows in the training split are counted and
   excluded (`n_train_attack_excluded` in the results JSON).
2. **Threshold calibrated on held-out benign validation flows only.** A threshold
   fitted on data containing the attacks it must catch is biased upward.

The scaler is fitted on training rows only; val/test are transformed with it.

### 2.2 Host-graph GNN (160 windows, 4 scenarios)

| Metric | Value |
|---|---|
| Window-label distribution | 40 Benign, 40 PortScan, 80 Infiltration |
| Train / test windows | 120 / 40 |
| **Window-id overlap between splits** | **0** |
| GNN accuracy | 1.0000 ± 0.0000 (3 seeds) |
| Macro-F1 / MCC | 1.0000 / 1.0000 |
| **Degree-only logistic-regression baseline** | **1.0000 ± 0.0000** |
| G3 latency gate | **PASS** — mean 1.289 ms, p95 1.790 ms vs 35 ms budget |

Architecture: two `SAGEConv` layers → concatenated global **mean + max** pooling
→ MLP, 60-second directed host graphs, window-level stratified splits.

**The GNN does not beat a degree-only logistic regression on this data.** This
is reported rather than buried, and it is the single most important caveat in
this phase — see §6.2.

Edge attributes genuinely enter message passing. PyG's `SAGEConv` has neither
`edge_dim` nor `edge_weight` and its `message()` receives only `x_j`, so an
explicit edge-message branch (`EdgeAttributeEncoder` + scatter onto the
destination node) carries them. `tests/test_gnn_detector.py` asserts that branch
receives a non-zero gradient.

### 2.3 Concept-drift monitoring

| Metric | Shifted stream | Control (no shift) |
|---|---|---|
| Alerts (mean of 2 seeds) | 4.5 | 0.0 |
| Recall on monitored shifted features | 1.000 | — |
| Monitoring coverage (shifted features watched) | 0.50–0.75 | — |

PSI sanity check: **0.015** for two independent samples of the same distribution
(conventionally "stable"), **7.564** for a 3σ shift (conventionally "significant").

Three monitors run: per-feature ADWIN on the top-K most variable features, ADWIN
on prediction confidence, and ADWIN on the detection rate. `delta = 0.002` is a
**false-positive rate bound, not an effect size** — smaller means more sensitive
and noisier. The negative control is reported rather than tuned away.

Drift output is evidence for a human to adjudicate. Nothing here retrains a
model or blocks traffic (`auto_retrain: false` in `configs/drift.yaml`).

### 2.4 Fusion — the one result that shows real value

| View | Recall | Precision |
|---|---|---|
| Per-flow view alone (autoencoder-style score) | 0.500 | 1.000 |
| Structural view alone (GNN-style probability) | 0.718 | 1.000 |
| **Fused (weighted soft voting)** | **0.987** | **1.000** |

This is the substantive argument for fusion, and it is structural rather than
incidental. The synthetic stream contains two regimes:

- **Exfiltration** — 15% of flows, individually unremarkable, collectively
  enormous. The per-flow view scores them at 0.2 (looks benign); only the
  structural view sees them.
- **Volumetric attack** — 15% of flows, each individually large but spread
  across many peers. The structural view scores them at 0.5 (unremarkable);
  only the per-flow view sees them.

Neither view covers both, so fusion is not redundant. 425 of 2,000 flows landed
in the `NeedsReview` band and were escalated rather than silently resolved.

Fusion weights are **fixed a priori** (0.6 per-flow / 0.4 structural) and never
fitted against labels. Choosing "the better model on the test set" would be
model selection on held-out data, inflating the reported number.

## 3. Output contract

`DetectionFusion.fuse()` emits, per flow: `flow_id`, `timestamp`, `label`,
`final_label`, `is_anomaly`, `needs_review`, `confidence`, `detection_source`,
plus `anomaly_score`, `graph_score`, `reconstruction_error` and
`gnn_attack_probability` for audit.

- `label` and `final_label` are **both emitted**. Downstream consumers and the
  phase spec refer to the same column by both names; emitting only one breaks
  whichever name the reader expected.
- `is_anomaly` is true for every escalation, **including** the `NeedsReview`
  band — escalation is the safe default.
- `detection_source` records which detector drove each decision
  (`both`, `anomaly_detector`, `graph_detector`, `both_disputed`), so every
  fused verdict is traceable to its inputs.
- Ground truth is attached **after** the decision is made and is used only for
  scoring. It never influences a label.

## 4. Bugs found during development

All ten were caught by end-to-end smoke tests rather than by reading the code.
Nine failed *silently* — they trained, converged, and reported plausible numbers.

| # | Bug | Symptom | Fix |
|---|---|---|---|
| 1 | **GNN labels desynchronised from graphs.** Targets were sliced in record order while the `DataLoader` shuffled the data. | Every epoch paired each graph with the wrong label. Loss frozen at exactly ln 2 = 0.6934; identical metrics across seeds; model predicted the majority class at 0.747 accuracy. | Label written onto `data.y` so batching carries it with the graph. |
| 2 | **Node traffic features zeroed.** `groupby(src) + groupby(dst)` aligns on the *union* of indices; hosts that were only a source came back `NaN` and were flattened to 0.0. | Exfiltration windows — a single 2-host pair — reported 0 bytes on both nodes while the edge carried 3.8 MB. The most discriminative feature was deleted for exactly the attack it should catch. | Align each view to the node index *before* adding. |
| 3 | **`SAGEConv(edge_dim=...)`** raises `TypeError` in PyG 2.8. | Edge attributes were never reaching the model. | Explicit `EdgeAttributeEncoder` + scatter branch; gradient asserted in tests. |
| 4 | **PSI divided by the wrong denominator.** Bin counts were divided by `expected.sum()` — the sum of the *raw values*, ≈0 for centred features — instead of `expected_counts.sum()`. | PSI returned ~4,900 for a normal shift and 54 for two identical samples. Should be ~2–4 and ~0.03. | Divide by the bin counts. |
| 5 | **ADWIN never primed.** Detectors were created empty in `fit()`. | A stream already shifted when monitoring began contains no *change*, so ADWIN correctly stayed silent while PSI fired. The two monitors disagreed. | Prime each detector with the reference samples. |
| 6 | **`drift_detected` read after the update loop.** | ADWIN raises the flag only on the detecting update and clears it on the next; sampling once after a loop always read `False`, so confidence and detection-rate monitors could never alert. | Sample inside the loop. |
| 7 | **River 0.22's `n_detections` is unreliable.** | `drift_detected` fired but `n_detections` stayed 0 on the C-backed build. | Count detections in the Python wrapper. |
| 8 | **Fusion invented scores.** Single-sample min-max normalisation substituted a fabricated "undecided" 0.5. | One fabricated value silently moved the fused decision. | Pass through when normalisation carries no information. |
| 9 | **Absent graph view still caused disputes.** | With no structural view there was nothing to disagree with, yet confident detections landed in `NeedsReview` because the surviving view was capped at 0.6 weight. | Renormalise weights over available views; assume agreement. |
| 10 | **Port-scan scanner was always the same host.** | The classifier could memorise an address instead of learning the fan-out structure. | Randomise the scanner per window. |

Bugs 1, 2, 4 and 6 are covered by named regression tests. Bug 1 is the clearest
argument for this project's testing approach: the code trained without error,
converged to a loss of exactly `ln 2`, and returned a plausible accuracy of
0.747 — it was only obviously wrong once three seeds returned *bit-identical*
metrics.

## 5. Deviations from the phase plan

### 5.1 The plan's autoencoder test is mathematically impossible

The plan's worked example asserts that reconstruction loss on 40-D i.i.d.
Gaussian input should roughly halve through a 16-D bottleneck. A rank-16 linear
map of an isotropic 40-D unit-variance Gaussian leaves `(40-16)/40 = 0.6` of the
variance irrecoverable, so the best achievable MSE is ~0.6 and **no autoencoder
can beat the identity baseline**. The claim is unattainable, not merely unmet.

Tests therefore use *structured* benign data — genuinely low-dimensional, so a
16-D bottleneck helps — and assert the property that matters: benign structure is
reconstructed better than anomaly noise. The arithmetic is asserted in
`TestAutoencoderPlanCorrection` so the correction is explicit rather than
folklore.

### 5.2 The plan's per-flow AE/GNN fusion assumed redundant detectors

The plan describes fusion as combining two detectors. They are not redundant, and
§2.4 quantifies why. The implementation preserves the plan's output contract but
treats fusion as a coverage problem, not an accuracy contest.

### 5.3 A dedicated graph simulator was required

The plan assumed the GNN could train on the lab captures. It cannot: those
captures contain three addresses, which form a graph of at most 3 nodes with 2
edges and no structure to learn. `src/data/graph_simulator.py` generates a
12-host network across four scenarios. **Phase 2 data was not modified.**

### 5.4 `river` must stay below 0.23

`river >= 0.26` requires `numpy >= 2.2.5`, which contradicts this project's
`numpy < 2.0.0` pin. River 0.22.0 provides the `river.drift.ADWIN` API used here
and works with NumPy 1.26.4. Pinned as `river>=0.22.0,<0.23.0` with the reason
recorded inline.

## 6. Limitations — what would and would not survive real data

### 6.1 The autoencoder result is the most transferable, and still not a claim

0.606 detection at a 0.016 false-alarm rate is a realistic operating point, not a
flattering one — the honest consequence of a 16-dimensional bottleneck on 28
heterogeneous features. But the underlying captures are synthetic, so this
measures the threshold-calibration machinery, not detection quality.

### 6.2 The GNN result would not survive real traffic

Four synthetic scenarios with deliberately distinct structural signatures are
trivially separable, and **a degree-only logistic regression matches the GNN
exactly.** On real traffic those signatures overlap heavily, and the honest
expectation is that a GNN's advantage — if any — appears only where local
neighbourhoods matter and degree summaries do not capture the pattern. This
experiment provides **no evidence that the GNN earns its complexity**.

The next step is not a bigger GNN. It is a harder benchmark: overlapping
scenarios, realistic base rates, and adversarial benign traffic that mimics
scan fan-out.

### 6.3 Base rates are absent

Real deployments face a base rate below 1%, where even 0.99 specificity yields
false alarms at 50× the true event count. Every number here is computed at the
synthetic base rates and does **not** model this. Precision under realistic base
rates is the most important missing evaluation.

### 6.4 The latency gate is measured, but on toy graphs

1.289 ms mean against a 35 ms budget leaves ~27× headroom, measured with CUDA
synchronisation and warm-up. But a 50-node/200-edge graph is small. Scalability
to enterprise-sized graphs is **open in the literature**; the research proposal
section 3.3 acknowledges this, and nothing here claims to resolve it.

### 6.5 Drift was tested on a synthetic shift

The monitors fire on a clean, large, known shift with zero control alerts —
close to the best case. Real drift is gradual, partial, and confounded with
legitimate change (re-addressing, new applications). Expect materially higher
false-alarm rates on real streams.

### 6.6 Out of scope

- No adversarial robustness or evasion testing.
- No encrypted-traffic (flow-metadata-only) evaluation.
- No live-capture integration; everything ran against files.
- Labels in the simulator are assigned per scenario, so the window-label
  derivation rule is tested for correctness on *real* label distributions but has
  not been validated against adversarial ground truth.
